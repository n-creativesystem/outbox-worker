Why Outbox Messenger?

分散システムにおいて、データベースの更新とメッセージブローカーへの送信をアトミックに行うことは困難です。
Outbox Messenger は、**Outboxパターン**の実装をシンプルにし、順序保証と高い信頼性を提供します。

In distributed systems, atomically updating the database and sending messages to a broker is challenging.
Outbox Messenger simplifies the **Outbox Pattern**, providing guaranteed ordering and high reliability.

順序制御 Strict Ordering

同一 aggregate_id 内のレコードはID順にソートされ、順序通りにPublishされます。失敗時は順序維持のため停止します。 Records with the same aggregate_id are sorted and published in order. Stops on failure to preserve order.

リトライ & Backoff Retry & Backoff

指数バックオフアルゴリズムを実装。一時的な障害時にシステムへの負荷を抑えつつ、自動的に再試行します。 Implements exponential backoff logic. Automatically retries during temporary failures while reducing load.

Multi-Backend Multi-Backend

AWS SNS と NATS JetStream に対応。aggregate_type (ARN/RN) に基づいて送信先を自動選択します。 Supports AWS SNS and NATS JetStream. Automatically selects the publisher based on aggregate_type (ARN/RN).

Architecture Flow

Outbox Messengerは、アプリケーションとメッセージブローカーの間を仲介します。ポーリングモデルを採用することで、複雑な分散トランザクションを回避します。

Outbox Messenger mediates between your app and message brokers. It uses a polling model to avoid complex distributed transactions.

Outbox Table

メッセージの一時保管場所です。

  • aggregate_type: 送信先 (ARN/RN)
  • aggregate_id: 順序制御のためのグループID
  • payload: JSONデータ

Temporary storage for messages.

  • aggregate_type: Destination (ARN/RN)
  • aggregate_id: Group ID for ordering
  • payload: JSON data

Outbox Worker

本ライブラリのコアコンポーネントです。

  • Polling: 定期的に未送信メッセージを取得
  • Grouping: aggregate_type で並列化、id で順序制御
  • State Mgmt: 送信成功時に sent_at を更新

The core component of this library.

  • Polling: Periodically fetches unsent messages.
  • Grouping: Parallel by aggregate_type, ordered by id.
  • State Mgmt: Updates sent_at on success.

Backend

メッセージの最終的な配送先です。

  • AWS SNS: ARN指定。Event属性を付与。
  • NATS JetStream: RN指定。Subject形式 topic.aggregate_id。

The final destination of the messages.

  • AWS SNS: Targeted via ARN. Includes Event attributes.
  • NATS JetStream: Targeted via RN. Subject: topic.aggregate_id.

Operational Notes

必須カラム Required Columns

アプリケーション側で以下のカラムを持つテーブルを作成してください。

Your application must create a table with the following columns.

Column Type Updater
aggregate_type VARCHAR (ARN/RN) App
aggregate_id VARCHAR (Group ID) App
payload JSON App
retry_at / sent_at DATETIME Worker

ARN / RN 形式 ARN / RN Format

Workerは aggregate_type を解析してバックエンドを選択します。

  • AWS SNS: arn:aws:sns:region:account:topic
  • NATS: rn::nats:::topic
Important: 形式が正しくない場合、WorkerはPublisherを選択できず送信に失敗します。

The worker selects the backend publisher by parsing aggregate_type.

  • AWS SNS: arn:aws:sns:region:account:topic
  • NATS: rn::nats:::topic
Important: If the format is invalid, the worker cannot select a publisher and will fail.

リトライ戦略 Retry Strategy

Publish失敗時、Workerは指数バックオフに基づいて retry_at と retry_count を更新します。

nextRetryTime = now + retryBackoff * (2 ^ retry_count)

retry_at が未来の時間になっているレコードは、その時間になるまでFetchされません（Skipされます）。

On failure, the worker updates retry_at and retry_count using exponential backoff.

nextRetryTime = now + retryBackoff * (2 ^ retry_count)

Records with a future retry_at are skipped during fetching until that time is reached.
